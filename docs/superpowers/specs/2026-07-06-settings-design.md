# 设置页设计

## 目标

给 Local Launcher 增加一个轻量设置页，用来管理全局行为、全局唤起快捷键和本地数据位置。
第一版只做已经明确需要的内容，避免把外观、凭据、备份和高级设置提前做重。

## 入口

主窗口头部右侧新增一个齿轮图标按钮，位置在“新增”按钮右侧。

选择这个入口的原因：

- 设置属于全局行为，应该在主操作区可见。
- 不占用卡片列表空间。
- 后续托盘菜单可以补一个“设置”辅助入口，但第一版不要求只依赖托盘。

## 页面形态

点击齿轮后在当前窗口打开设置视图，不开新窗口，不做浮层。设置视图使用现有浅色桌面工具风格：

- 顶部标题栏：`设置` 和关闭按钮。
- 左侧导航：`常规`、`快捷键`、`数据`、`关于`。
- 右侧显示当前分组内容。

第一版实现为应用内模式，类似现有新增/编辑流程。保存策略为“修改即保存”；失败时显示现有消息提示。

## 常规

常规分组包含三个持续状态开关：

- `开机自启`：登录 Windows 后自动启动本工具。
- `启动时显示主窗口`：程序启动后是否直接显示主窗口。
- `关闭窗口时最小化到托盘`：点击窗口关闭按钮时隐藏到托盘，而不是退出。

默认值：

- `开机自启`：关闭。
- `启动时显示主窗口`：开启。
- `关闭窗口时最小化到托盘`：开启。

## 快捷入口

桌面快捷方式不是持续设置，不做成开关。

常规分组里提供 `创建桌面快捷方式` 按钮：

- 如果桌面快捷方式不存在，按钮显示 `创建快捷方式`。
- 如果已存在，按钮显示 `已存在`，可以禁用。
- 创建失败时显示错误消息。

## 快捷键

快捷键分组包含：

- `启用全局唤起` 开关。
- 快捷键输入框，默认 `Ctrl + Alt + Space`。

行为：

- 启用后，按快捷键显示或隐藏主窗口。
- 快捷键注册失败时，保持设置不生效并显示错误消息。
- 第一版只需要支持一个全局快捷键。

## 数据

数据分组显示当前数据文件位置，并提供 `打开位置` 按钮。

数据文件仍使用现有 JSON 配置文件。导入和导出按钮可以暂时保留在底部，不强制迁移进设置页。

## 关于

关于分组显示：

- 应用名称。
- 当前版本。
- 数据存储说明：账号密码第一版仍不保存密码，只保存账号和备注。

## 数据模型

现有 `LauncherConfig` 需要增加 `settings` 字段。为了兼容旧 JSON，缺失 `settings` 时使用默认值。

建议结构：

```rust
pub struct LauncherSettings {
    pub launch_at_login: bool,
    pub show_window_on_startup: bool,
    pub close_to_tray: bool,
    pub global_hotkey_enabled: bool,
    pub global_hotkey: String,
}
```

旧配置加载后保存时可以补齐 `settings` 字段。

## Windows 集成

开机自启使用当前用户的启动项，不需要管理员权限。

实现优先级：

1. 当前用户启动目录快捷方式。
2. 如果快捷方式方案不可用，再考虑注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`。

桌面快捷方式同样使用 Windows Shell API 创建 `.lnk`。

## 错误处理

所有系统集成操作都需要返回明确错误：

- 创建自启项失败。
- 删除自启项失败。
- 创建桌面快捷方式失败。
- 注册全局快捷键失败。
- 打开数据目录失败。

错误统一进入现有状态消息区域，不弹命令行窗口。

## 测试

最小验证范围：

- 旧 JSON 缺少 `settings` 时可以加载，并使用默认设置。
- 新设置保存后再次启动能恢复。
- 开关状态变化会更新配置。
- 桌面快捷方式按钮不会把状态误存成布尔设置。
- 全局快捷键字符串解析失败时不会崩溃。

## 不做

第一版不做这些内容：

- 外观主题和卡片密度设置。
- 密码保存和凭据管理。
- 自动备份。
- 多套快捷键。
- 高级调试设置。
